## 1. 产品目标和不变边界

目标：独立安装的本地 macOS Corn Bot，保持已选定的 Grok 风格界面和原创玉米头像。用户能配置模型、真实聊天、让任务后台执行，同时继续问问题、查询进度、补充要求、停止指定任务并收到一次可靠成果交付。

- 以可感知的效果选型。当前实现用 DSH/Claw；OpenClaw、Mastra 是候选底座，不预先宣布必须保留或替换 DSH。底座选择由 P1 固化，不先写大型通用 Orchestrator。
- 保留已做的 Corn React/Electron UI、原创素材和可复用的产品契约；如果替换执行底座，通过适配边界替换，不把两个 Agent Loop 叠加管理同一执行会话。
- Main 持有运行时认证、凭据写入和数据库。Renderer 只获得受限 IPC；用户主动输入 Key 的单向写入遵循已确认边界，不回显存量 Key、不持久保存于 UI 草稿或日志。
- App 和数据归 Corn。不得访问/修改安装的 DSH、`~/.dsh` 或其他应用的个人配置；不自动导入开发 Key、现有 Bot 或记忆。
- Grok 调查、Kit 和提取素材是研究输入；不复制 Grok 私有执行代码、原头像几何或未经授权的发布资源。Corn 自有素材继续沿用锁定来源。
- 现有 PTC 外层禁用结论保留。以后开放必须另证明嵌套工具逐次治理；不能由后台任务实现顺带放行。

## 5. P1：底座选择，不凭文档宣布胜者

优先比较 OpenClaw 的完整运行时嵌入路线、Mastra 的 TypeScript SDK 路线，与现有 DSH 的最小适配对照。公开能力、固定提交和限制见[底座调研](../research/runtime-options-2026-10-11.md)；Grok 调查用于效果契约，不用于证明某底座已达标。

### 5.1 先做可只读完成的审计

- 固定真实安装版本/源码提交及组件范围；公开 API、模型支持、本地存储、停止边界、审批能力、Node/Electron 打包依赖分别列证据。
- 不要求取得 Grok Temporal Worker；不照搬它的私有协议、旧三队列或未证实抢占 SLA。
- 制定Main-only RuntimeAdapter能力表：模型设置、身份/会话创建、消息受理、只读历史、实时流、审批结算、取消、任务控制检查、恢复，以及逐次工具治理/权限/审计。每项标supported / conditional / unavailable。
- **治理是选型硬门槛，不限定必须使用Claw这个实现**：每次真实工具派发须经过可信、可审计的强制检查，等价覆盖当前Claw Gate/权限/审批绑定；审批等待后重查、默认拒绝未知/过期控制、停止fencing和完整审计归属必须能实现。PTC只有外层拒绝证据，未证明嵌套逐次检查前不开放。OpenClaw/Mastra自带审批或hook并不自动证明等价，移植/适配代价记入ADR。
- IPC 始终是产品命令；不得暴露通用 RPC/fetch/SQL。框架不同的 ID 由 Main 映射，UI 使用稳定 botId/conversationId/runId。

### 5.2 恢复验证后统一比较

只用一主会话加一Worker、同一小任务串行比较：后台未完成时独立回复；改要求；准确查询；停止指定任务；一次交付；重启不盲目重放。记录响应时延、CPU/内存/进程数、模型限流及实际停止情况。先fake provider/无副作用任务，真实比较继续暂停。

真实模型调用前由维护者单独明确Provider、模型ID、请求次数上限（包含框架内部重试/后台调用）和停止条件。Key由用户在经审查的Corn受限配置入口手动输入（可为独立隔离的测试构建，不要求先合入主产品）；不读取model.env，不自动导出/复制Key给其它底座，不在聊天索要Key。当前main配置页还是fixture，未接通可信入口前该条件尚未满足，不能以选型名义直接消费现有Key。当前先做静态对照；实际限额没有给出时不调用模型，也不自行假定一个预算。

不能把 OpenClaw 临时 BTW 默认不入主历史当成持久聊天已交付；不能把 Mastra background/SSE 或 beta durable 的存在当成可靠恢复保证；不能把 DSH 两个 Session 当成前台低延迟已保证。

### 5.3 决策产物与退出条件

单独 ADR（建议 0007，创建前确认编号）记录选择、固定版本、真实证据、必要自研范围、包体/进程代价和迁移策略。只选择一个执行 Loop。若更换后端，UI 与原创资产保留；旧 DSH 数据只按明确的 Corn-only 迁移方案处理，不读取现有其他应用凭据。

DSH路线需先解决：Session-only模型选择、Host侧RunControl与只读恢复。其它路线需证明等价能力。**选型期间不改上游DSH、不改Claw实现或策略。** 可以只读审计公开扩展点；缺能力时只记录所需Corn适配/上游补丁的范围、成本和门禁。只有选定路线后、取得独立明确的改动授权，才实施上游补丁或策略修改。本计划不是该授权。

没有候选通过真实门禁就保留选型pending，静态对照可以先形成建议；#15 N1/N3及底座无关的UI/契约可继续，不硬宣布底座完成。

## 7. P3：真实前台聊天，一条完整链路

### 7.1 最小持久化和事实源

先固定 DB 驱动并通过所选打包运行时验证；现有 node:sqlite 只是已测候选。单 Main writer、WAL、外键、版本迁移、备份/失败回退。表先满足 Bot、Conversation、Binding、消息受理幂等、UI 偏好；不要让 Renderer 读 DB。

运行时日志是执行/对话事实源；Corn 保存产品身份、关联、投递状态与可重建投影。全局 Provider/Key/default 不在 SQLite 再存第二份权威配置；app_settings 只保存产品偏好或可重建缓存。

### 7.2 真实 Repository、流与审批

创建/读取身份 → 确保策略/preset → 创建匹配 Session → 校验 → 绑定 → 合法模型 → ready。每阶段部分失败有可修复记录，无普通会话降级。DSH 路线复用已审计 Registry 事务；更换底座则遵守选中适配器的身份及策略协议。

Main-backed Repository 替换正常入口 fixture；fixture 仅保留明确开发路由。消息 requestId、HTTP rpcId、Turn 不混用；去重重试不生成第二条任务。流处理 opening snapshot、durable seq、临时 assistant stream；断线不当成功，补历史不重复消息。

审批按实际请求/代次/动作绑定；仅实现运行时真实答案，不让普通聊天文本代替审批。当前对话取消不误取消后台任务。权限/核心设定/技能管理先读后写，经公开接口审计开放；Bot 模型覆盖先过下面的隔离门禁。

### 7.3 模型隔离门禁

两个 Bot/Session，一个覆盖、一个跟随全局；实际请求及重启后正确，修改覆盖不改全局/另一个 Bot。DSH selectModel 异步修改全局，禁止先改后恢复；可研究公开 installModelSelection/agent/request seam，但不能靠 append model/selection 假装热切换缓存已生效。公开服务不满足时记录最小扩展/上游补丁成本或候选重选；选型期间不实施上游改动。

**退出条件**：正常页面创建真实 Bot、配置模型、真实流式回复、一次审批、取消、重开历史可用，示例标识正确消失；假模型测试和真实模型请求证据分开。

## 8. P4：第一条完整后台任务

首版后台并发默认1，前台保留独立响应能力；默认不做多层委派、跨 Bot 自动调度或模型请求抢占。创建任务持久化后立即返回 runId，不 await Worker 完成。

### 8.1 最小域模型

- TaskRun 表示持续目标；RunAttempt 表示一次执行，绑定 workerSessionId、代次与模型选择。当前 Attempt 指针与历史绑定分开。
- RunDirective 关联规范用户消息/必要可重试正文，具有稳定 ID、单 Run 递增 revision、独立 delivery/adoption 状态；不能只存 pendingSteer 字符串。
- ControlOp 表示停止等可收敛操作；Completion/Outbox 表示终态和一次交付；事件游标与投影在同一事务更新。
- 暂不新增没有独立生命周期的 Workstream 层。出现跨多个 Run 持续协作需求时再加，不改变 UI 对用户目标的连续性。

### 8.2 同包实现控制与最小恢复

Main 的状态须接入可信执行边界。工具每次真实派发检查 Attempt/停止代次、限制 revision、租约；等待审批/资源后重查。停止或收紧之后批准旧审批仍不能执行。DSH 可审计公开 tools.guard；其它底座验证对应强制检查，不复制 Claw 实现。

自然语言改方向和结构化强制限制分开。主张可强制的限制必须有工具/路径范围和执行检查；未覆盖范围不能标 enforced。失联/未知控制状态对受控 Worker 阻止新副作用。

停止：封闭新派发 → 请求运行时取消 → 处理属于此 Run 的残余 Inbox/子工作/外部 Job → 确认停止和 fencing → 释放资源 → cancelled。未确认显示 stopping/stop_partial/unknown，保留资源隔离，不虚报回滚。

首次副作用即具备租约：前台和后台共同遵守工作树/浏览器/设备仲裁。代码工作使用独立 worktree 或写租约；同一真实 Mac 只有一个输入控制者；租约有 fencing、截止期限和人工接管。

启动/重启先只读对账再决定执行。DSH 用 projections 的 asOfSeq 与 page(throughSeq)核对；冷 follow 会 promote Agent，不能为了恢复卡片直接激活已停 Worker。未知非幂等副作用不自动重试。

### 8.3 完成和 UI

终态、稳定 completionId 和 Outbox 同事务；任务卡及成果引用幂等更新，不等待主模型空闲。需要解释的摘要进入低优先级前台队列，不能阻塞用户聊天。旧 Attempt/revision/stopEpoch 的结果不覆盖当前成功，但日志/成果保留可查询。

RunCard 显示 queued/running/waiting/停止中/完成/失败与真实摘要；主 Composer 默认聊天，回复任务卡有明确目标。进度从状态投影读取，不频繁调用模型、不编造百分比。受理不是采纳，模型确认不是强制执行保证。

**退出条件**：一条真实后台任务未完成时能独立问答、查询、停止；旧审批不能复活；完成交付一次；刷新状态可恢复。以上能力必须一起交付，不能只上线异步启动按钮。

## 9. P5：连续改向和长期恢复

在 P4 上加强三条快速连续修订、结束边界插话、网络未知受理、恢复和副作用核对。Directive FIFO 保留原始约束；逐条采纳或明确完整替代关系，adoptedRevision 不简单取最大数掩盖缺口。

明确同一任务复用 Worker 与新 Attempt 的条件，scope/模型/身份改变必须重新验证。停止后的旧消息不自动开启下一 Turn。每次恢复结果与 Attempt/来源事件关联，不把关流或一句 assistant 文本当作完整任务成功。

复杂 BackgroundJob/awaitOrYield、Shell 后台化、暂停/恢复检查点后置；只有实际可取消/可恢复的工具才开放暂停。默认不凭 readOnlyHint 免审，也不承诺通用 MCP 或模型采样立即抢占。

## 10. P6：真实本机操作

按 Browser → 受控命令/文件 → Mac Desktop 的能力包推进；桌面系统授权按用户实机流程，不改变别的应用配置。前后台共用资源仲裁；人工接管优先，停止后不再发新键鼠事件。

工具状态明确列出 cancel capability、拥有的 Job/进程/浏览器 Context；释放订阅不算终止工作。中断/超时/权限撤销/Host 崩溃均有真实停稳证据。恢复不能重复邮件、支付、删除等不可逆动作。

GUI 操作的速度和成本以本机单场景实测，不因安装框架就声称完整 Computer Use 已交付。PTC 若产品需要再做独立治理工作包，不作为本阶段隐含前置。
